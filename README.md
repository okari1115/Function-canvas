# Function Canvas

**C / Python の関数構成・依存関係・設計メモを、ブラウザ上で整理するビジュアルツール。**

関数の数が増えても、**「機能グループ → 主要関数 → 補助関数」** の順に表示を切り替えながら、プログラムの全体像と詳細を確認できます。関数の責務、入出力、変更する状態、事前条件、契約などをメモし、設計を見直すためのアプリです。

**[▶ Function Canvas を使ってみる](https://okari1115.github.io/Function-canvas/)**  
[ソースコード（GitHub）](https://github.com/okari1115/Function-canvas)

> [!NOTE]
> **利用だけならインストール・ログイン・ビルドは不要です。** 上のリンクをPCまたはiPadのブラウザで開いてください。自分の端末・サイトで動かす方法は[インストールと起動](#インストールと起動)にあります。
>
> 42の学習にも使える個人制作ツールであり、42公式のサービスではありません。

## できること

| 機能 | 内容 |
| --- | --- |
| プロジェクト管理 | `libft`、`ft_printf`、`push_swap` など、プロジェクト別のワークスペースを作成・複製・切り替え |
| C / Python モード | プロジェクトごとに解析対象言語を選択 |
| ソース解析 | `.c` / `.h` / `.py`、複数ファイル、ZIP、対応ブラウザでは TAR.GZ を読み込む |
| 関数の自動検出 | 関数名、引数、ソースファイル、行番号、直接呼び出しの関係を抽出 |
| 機能マップ | 「入力解析・検証」「ソート制御」「操作実行」「履歴・最適化」「出力・計測」「初期化・後始末」「その他・共通」へ**推定**分類 |
| 階層表示 | 主要関数の内側に補助関数を折りたたむ。前後1〜2段階に絞った表示も可能 |
| 関数設計メモ | 責務、入力、変更するもの、変更しないもの、依存関係、事前条件、契約を編集 |
| 依存関係の編集 | 矢印の作成・付け替え・削除。自動検出と手動接続を区別 |
| ソース表示 | 関数から対応するファイル・行番号へジャンプ。未解決の呼び出しを一覧表示 |
| 依存関係の分析 | 循環、孤立、到達可能性、接続の集中などを確認 |
| バックアップ | プロジェクト単位／全プロジェクトのJSON書き出し・読み込み |
| iPad対応 | タッチ操作、二本指ズーム、ホーム画面に追加できるPWA |

## はじめて使う：5分で試す

1. **[Function Canvasを開く](https://okari1115.github.io/Function-canvas/)**。プロジェクト一覧が表示されたら、既存のプロジェクトの **「開く」** を選びます。
2. 上部の **「◫ 機能マップ」** を選び、機能グループをクリックします。
3. 関数カードを選ぶと、右側の **「関数設計メモ」** に詳細が表示されます。実際に「責務」や「契約」を編集してみてください。
4. **「⌘ 通常キャンバス」** に切り替えると、関数を矢印でつないだ図を表示できます。ノードはドラッグで移動できます。
5. **「＋ 新しい関数」** でノードを追加し、**「↗ 接続する」** またはノード右端の青い丸からのドラッグで接続してみてください。
6. 試した内容を残す場合は **「↓ JSON保存」** で保存します。

**最初から自分のコードを解析したい場合**は、次の[ソースの読み込み手順](#c--python-のソースを読み込む)に進んでください。

## 画面の見方と基本操作

### 画面の3つの領域

| 場所 | 役割 |
| --- | --- |
| 上部 | プロジェクト・解析言語の切り替え、読み込み、保存、機能マップ／通常キャンバスの切り替え |
| 中央 | 機能グループ、関数ノード、依存関係の矢印を表示・操作 |
| 右側（iPadの狭い画面では下側） | 選択した関数の設計メモ、所属グループ、補助関数の表示方法、ソース位置を編集・確認 |

### 2種類の表示

**◫ 機能マップ（全体像をつかむ）**

- 最初は機能グループ単位で表示します。
- グループを選ぶと、所属する主要関数と依存関係を確認できます。
- **「関数全体」**／**「選択関数に集中」** で表示を切り替えられます。集中表示は前後1段階／2段階を選べます。
- 関数カードや内部補助関数を選択すると、設計メモを開けます。
- **「⌂ 全体」** でグループ一覧に戻ります。

**⌘ 通常キャンバス（関数や矢印を編集する）**

| やりたいこと | 操作 |
| --- | --- |
| 関数を選択・編集 | ノードをクリック／タップ → 右側の設計メモを編集 |
| 関数を移動 | ノードをドラッグ。タッチ操作では設計メモ内の上下左右ボタンも使用可 |
| 手動で接続 | **「↗ 接続する」** → 接続元 → 接続先、またはノード右端の青い丸から接続先までドラッグ |
| 矢印の接続先を変更 | 既存の矢印を選び、表示された端点を別の関数へドラッグ |
| 矢印を削除 | 矢印を選び **「選択した矢印を削除」**、または **「↗ 接続一覧・削除」** |
| 関数を検索 | **「⌕ 関数を検索」** に名前・責務・契約を入力 |
| 見やすく配置 | **「▦ 自動整列」**、**「▸ 全部たたむ」**、**「▾ 全部開く」** |
| 拡大・縮小 | **「＋ / －」**、iPadでは二本指のピンチ操作。**「全体表示」** で収める |
| 依存関係を調べる | **「◎ 依存関係の分析」** |
| 未解決の呼び出しを見る | **「? 未解決」** |

> [!TIP]
> 関数同士の**実際の呼び出し関係**と、見やすさのための**表示上の分類**は別管理です。分類を変更しても、呼び出し関係が勝手に書き換わるわけではありません。

## C / Python のソースを読み込む

1. **「＋ 新規」** からプロジェクトを作成するか、既存プロジェクトを開きます。
2. 画面上部の **「言語」** で **C** または **Python** を選択します。
3. **「⇧ ソース / ZIP / TAR」** をクリック／タップしてファイルを選びます。
   - **Cモード：** `.c`、`.h`
   - **Pythonモード：** `.py`
   - **一括取り込み：** `.zip`、`.tar.gz`、`.tgz`（TAR.GZはブラウザの対応が必要）
4. 表示される **「ソース解析の確認」** で、追加・更新される関数、依存関係、未解決件数を確認します。
5. 問題なければ **「解析結果を反映する」** を押します。
6. **「◫ 機能マップ」** から分類結果を確認するか、**「⌘ 通常キャンバス」** で詳細な依存関係を確認します。

**再読み込み時の扱い：** 同じファイルパスのソースは更新され、未選択の読み込み済みファイルは保持して再解析します。手書きの設計メモ・ノード位置・手動接続は基本的に維持し、自動接続は新しい解析結果で更新します。定義が見つからなくなった関数は即削除せず、その状態を表示します。

**取り込みの上限（v5.1）：** ファイル150件まで、検出関数400件まで、ZIP/TAR.GZは8MBまで。1ファイル40万文字・ソース合計約170万文字までです。ファイルの組み合わせやブラウザのメモリによっては、上限以内でも読み込めない場合があります。

### ソースコードを見る

ノードを選択 → 右側の設計メモの **「⌘ 該当するソースを開く」** を選ぶと、保存されたソースの該当箇所を表示します。解析対象外の呼び出しは **「? 未解決」** から確認できます。

## 機能グループと関数の折りたたみ

### 機能グループは「自動推定」

所属グループの候補は、主に**関数名とファイル名**をもとに決めています。たとえば `parse_args()` は入力解析、`sort_complex()` はソート制御、`print_history()` は出力・計測の候補になります。ただし、**ソースの意味を完全に理解して責務を確定する機能ではありません**。

分類が違う場合は、関数を選択し、設計メモ上部の **「◫ 機能グループ（表示上の分類）」→「所属グループ」** を変更してください。手動で確定した分類は、ソース再読み込み後も保持される設計です。**「自動推定に戻す」** で解除できます。

### `static` 補助関数の収納

Cでは、解析できた範囲で**同じ翻訳単位内の呼び出し元が1つ**の`static`関数を、その呼び出し元の内部へまとめる候補として扱います。複数の関数から使われる補助関数は、原則独立表示します。

- 親ノードの **「内部補助関数」** で展開・折りたたみます。
- 設計メモの **「関数の階層化・折りたたみ」** から自動判定・独立表示・親の手動指定を変更できます。
- 折りたたんでも関数定義や依存関係のデータそのものは消えません。

> [!IMPORTANT]
> Cのファイルスコープ`static`は、**特定の関数の内側に定義されている**という意味ではありません。Function Canvasの収納は、あくまで**表示上の整理**です。関数ポインタなどで呼び出される場合、自動判定は不完全なことがあります。

## 保存・バックアップ・別端末への移行

### ブラウザ内の自動保存

編集内容は原則として**使用中のブラウザのローカルストレージ**へ自動保存されます。アカウントやクラウド同期はありません。同じURLでも**別PC・別ブラウザ・Safariとホーム画面のPWA**では保存領域が異なる場合があります。

### JSONの書き出し・読み込み

| 目的 | 操作 |
| --- | --- |
| 現在のプロジェクトだけバックアップ | 上部の **「↓ JSON保存」** |
| 現在のプロジェクトへJSONを復元 | 上部の **「↑ 読み込み」** |
| 全プロジェクトをまとめて保存 | **「▦ プロジェクト一覧」→「↓ 全プロジェクトを保存」** |
| 全プロジェクトを別端末へ移す | 新端末のプロジェクト一覧で **「↑ 全プロジェクトを読み込む」** |

**全プロジェクトの読み込みは、現在のプロジェクト一覧を置き換えます。** 必要なら読み込み前に保存してください。

> [!WARNING]
> **ソースを取り込んだJSONには、元のソースコードも含まれる場合があります。** 共有する前に内容を確認してください。また、ブラウザの保存容量を超えると自動保存に失敗することがあるため、特に大規模なプロジェクトでは定期的なJSONバックアップをおすすめします。

## インストールと起動

### A. 公開版を使う（いちばん簡単）

**[https://okari1115.github.io/Function-canvas/](https://okari1115.github.io/Function-canvas/)** を開くだけで利用できます。PCへのインストールやPython/Cの開発環境は不要です。

### B. iPadのホーム画面へ追加する（PWA）

1. iPadの **Safari** で公開版を開きます。
2. **共有** ボタンから **「ホーム画面に追加」** を選びます（表示されない場合はメニューを展開してください）。
3. 項目がある場合は **「Webアプリとして開く」** を有効にします。
4. **「追加」** を押し、ホーム画面のアイコンから起動します。

アプリ風に全画面で使えます。初回表示にはネットワークが必要です。読み込み済みのアプリ本体はService Workerでキャッシュされますが、オフライン動作や保存内容はブラウザの設定・キャッシュ状態に依存します。

**注意：** Safariで使っていたプロジェクトがPWA側に見えないときは、Safari側で **「全プロジェクトを保存」** → PWA側で **「全プロジェクトを読み込む」** を試してください。

### C. ソースを取得してローカルで動かす

このリポジトリのファイルを取得し、**`index.html` とJavaScriptファイルを同じディレクトリ**へ置きます。Node.js、npm、Tree-sitterのインストール、ビルド作業は不要です。

```bash
# GitHubのリポジトリを取得
git clone https://github.com/okari1115/Function-canvas.git
cd Function-canvas

# Python 3 の簡易HTTPサーバーで起動
python3 -m http.server 8000
```

ブラウザから **http://localhost:8000/** を開いてください。終了するにはターミナルで `Ctrl+C` を押します。

`index.html` を直接ダブルクリックして開くより、ローカルHTTPサーバー経由での動作確認をおすすめします。PWAのインストール・キャッシュ動作はHTTPSで公開したサイトで確認してください。

### D. 自分のGitHub Pagesに設置する

1. GitHubでリポジトリを作成し、`index.html`、`parser.js`、`classifier.js`、`jszip.min.js`、`sw.js`、`manifest.webmanifest`、アイコンPNG、`README.md` などを**公開対象フォルダの直下**に置きます。
2. リポジトリの **Settings → Pages** を開きます。
3. **Build and deployment → Source** を **Deploy from a branch** に設定します。
4. 公開するブランチ（例：`main`）と **`/(root)`** を選び **Save** します。
5. GitHub Pagesの公開URLへアクセスします。

詳しくは[GitHub公式：GitHub Pagesの公開元設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)を参照してください。

## 解析精度と既知の制約

- **Tree-sitterやAIモデルは組み込まれていません。** 現在はブラウザ内で動く軽量な静的解析器を使用しています。
- Cの複雑な宣言、マクロ、関数ポインタ、条件付きコンパイル、Pythonの動的呼び出しや属性解決などは、正確に解析できない場合があります。
- **「未解決の呼び出し」は必ずしもエラーではありません。** 標準ライブラリ、外部ライブラリ、解析対象外の関数も含まれます。
- 機能グループの自動分類は、主に関数名・ファイル名による**推定**です。正確な責務や設計意図は、利用者が確認してください。
- ソース解析は基本的に読み取り専用です。Function Canvas上で変更した設計メモが元の`.c`や`.py`ファイルに書き戻されることはありません。
- ソースコードの読み込み・静的解析はブラウザ内で行い、アプリの解析処理がソースコードを外部APIへ送信する仕組みはありません。ただし、GitHub Pagesからアプリ本体を取得する通信は発生します。
- iPad向けの表示・タッチ操作を備えていますが、OSやブラウザのバージョンによって挙動が異なる場合があります。

## 困ったときは

| 症状 | 確認すること |
| --- | --- |
| 画面が真っ白・ボタンが反応しない | `index.html` と `parser.js` / `classifier.js` / `jszip.min.js` が同じ階層に配置されているか確認。ブラウザの開発者ツールでエラーを見る |
| 更新したのに古い画面が出る | ページの再読み込み・PWAの再起動を試す。Service Workerのキャッシュ更新に時間差が出ることがあります |
| 関数が検出されない | 上部のC/Pythonモードとファイル拡張子を確認。複雑な構文は解析対象外の可能性があります |
| ZIPを取り込めない | `jszip.min.js` の配置、圧縮形式、8MB上限を確認 |
| TAR.GZを取り込めない | `DecompressionStream` に対応するブラウザで試すか、ZIPへ変換する |
| 予想と違う機能グループへ入る | 関数を選んで **「所属グループ」** を手動で変更 |
| ノードが見つからない | 関数検索を使う。`static`関数は親ノードの内部に収納されていることがあります |
| 保存できませんと表示される | ブラウザの保存容量不足の可能性。**JSONへ書き出し**、不要なデータを整理する前にバックアップを取る |
| iPadのPWAにプロジェクトがない | SafariとPWAで保存領域が異なる場合があるため、JSONで移行する |
| ソースを更新したのに古い関数が残る | 再解析で見つからなくなった定義は自動削除せず、`ソース上に見つからない` として保持する仕様です |

## ファイル構成・技術情報

```text
Function-canvas/
├── index.html           # 画面、ノード操作、プロジェクト・保存処理
├── parser.js            # C/Pythonの軽量な静的解析
├── classifier.js        # 機能グループの推定・表示用の構成計算
├── jszip.min.js         # ZIPの読み込み（外部ライブラリ）
├── sw.js                # PWA用Service Worker
├── manifest.webmanifest # PWAの名前・アイコン・起動設定
├── icon-192.png
├── icon-512.png
├── apple-touch-icon.png
├── JSZip_LICENSE.md     # ZIPライブラリのライセンス
└── README.md
```

- **実装：** HTML / CSS / JavaScript。サーバーサイド処理・ビルド工程なし。
- **保存先：** ブラウザの `localStorage`。別端末への共有はJSONファイルを介して行います。
- **設計方針：** ソースから抽出した事実、表示上の分類、手書きの設計メモをなるべく独立させ、再解析でも手作業を保持します。
- **第三者ライブラリ：** JSZip。ライセンスは [`JSZip_LICENSE.md`](./JSZip_LICENSE.md) を参照してください。

### v5.1での主な修正

通常キャンバスでノードをクリックすると選択が解除される問題、JSON復元時の座標の切り詰め、グループ切り替え後のフォーカス状態、ソースやグループを編集した後の表示更新などを修正しています。

---

**使い方の流れ：** ソースを読み込む → 自動生成された関数・依存関係を確認する → 機能グループを必要に応じて調整する → 設計メモを書く → JSONでバックアップする。
